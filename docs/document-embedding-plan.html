knowra 文档向量化功能方案（Cloud Embedding）

本文沉淀"在现有文档解析与分块能力之后，新增基于云端嵌入模型的文档向量化能力"的方案。 首版采用云端 API 服务 tumuer.me 提供的 Qwen/Qwen3-Embedding-0.6B 模型， 通过 OpenAI 兼容接口实现 chunk 文本的批量向量化。向量化完成后生成 embedding 结果并持久化； 首版不包含向量存储（pgvector 索引写入）和语义检索能力，这些将在后续变更中独立实现。

阶段：方案探索 日期：2026-07-15 推荐变更：add-document-embedding 嵌入模型：Qwen/Qwen3-Embedding-0.6B API 类型：OpenAI 兼容（tumuer.me 云端） 默认维度：1024 上下文长度：32K tokens 前置能力：document-parsing + document-chunking 已归档 后续规划：向量存储 & 语义检索（独立变更）

1. 背景与产品意图

1.1 当前进展

knowra 已完成以下核心能力的实现与归档：

① 文件上传 用户上传 PDF / DOCX / PPTX / MD / TXT 到私有存储，归属当前用户。
② 文档解析 Docling 解析器提取 Markdown、纯文本、结构化 JSON 和结构片段（segments）。
③ 文档分块 Docling HybridChunker 生成 token 感知的 chunk，包含文本、上下文文本、标题路径和页码。
④ 向量化 ← 本变更 将每个 chunk 的文本通过云端嵌入模型转换为固定维度向量。

1.2 产品意图

向量化是 knowra「接入资料 → 解析内容 → 分块与索引 → 用户提问 → 检索相关片段 → 生成带引用的回答」 核心工作流中从"文档理解"过渡到"语义检索"的关键桥梁：

  • 将人类可读的 chunk 文本转化为机器可计算的稠密向量表示。
  • 为后续 pgvector 向量存储和语义相似度检索提供标准化的向量输入。
  • 使用云端模型避免本地 GPU 依赖，降低部署复杂度。
  • 保持模块化设计，嵌入模型可替换（后续可切换其他 Qwen / BGE / Jina 模型）。

1.3 范围边界

首版范围（本变更）
  • 配置云端 embedding API 连接参数（base_url、api_key、模型名、维度等）。
  • 定义 embedding 作业模型和 embedding 结果模型。
  • 实现 OpenAI 兼容的 embedding API 客户端适配器。
  • 在分块成功后自动触发首次向量化（与"解析即分块"模式一致）。
  • 提供重新向量化 API（当用户切换嵌入模型或维度时）。
  • 持久化向量结果到 document_embeddings 表（每 chunk 存为浮点数组 / JSON）。
  • 支持 graceful shutdown 期间标记未完成作业。
明确不在首版范围
  • ❌ 不写入 pgvector 向量索引（即不创建 vector(1024) 类型列和 IVFFlat/HNSW 索引）。
  • ❌ 不实现语义检索（不提供 POST /api/search 或相似度查询 API）。
  • ❌ 不实现本地 embedding 模型推理。
  • ❌ 不自动同步多个 embedding 版本（每次重新向量化会 supersede 旧结果，与 chunk 作业语义一致）。

2. 云端嵌入模型 API（tumuer.me）

2.1 服务概览

采用 tumuer.me 提供的云端 Embedding & Reranker 服务，提供 OpenAI 兼容的 POST /v1/embeddings 接口。文档地址： https://embedding-docs.tumuer.me/api/embeddings.html

2.2 Endpoint & 认证

项目值
完整地址https://router.tumuer.me/v1/embeddings
HTTP 方法POST
认证方式Authorization: Bearer <api_key>
Content-Typeapplication/json
接口类型OpenAI 兼容（可直接使用 openai Python SDK）

2.3 请求体（JSON）

字段类型必填说明
model string 是 模型名称，首版使用 Qwen/Qwen3-Embedding-0.6B
input string | string[] 是 输入文本或文本数组；首版使用批量模式（文本数组）以提高效率
encoding_format "float" | "base64" 否 返回向量格式，默认 float。首版使用 float
dimensions number 否 期望输出维度，部分模型支持降维。Qwen3-Embedding-0.6B 可选 32/64/128/256/512/768/1024

2.4 返回体（JSON）

字段类型说明
object"list"固定为 list
modelstring实际使用的模型
dataArray<{ index: number; embedding: number[] }>向量结果列表，index 对应输入顺序，embedding 为浮点数组
usageobjecttoken 统计（prompt_tokens、total_tokens）

2.5 请求示例（Python SDK）

from openai import OpenAI

client = OpenAI(
    base_url="https://router.tumuer.me/v1",
    api_key="<your_api_key>",
)

response = client.embeddings.create(
    model="Qwen/Qwen3-Embedding-0.6B",
    input=["文本一", "文本二", "文本三"],
    encoding_format="float",
)

for item in response.data:
    print(f"index={item.index}, dims={len(item.embedding)}")
# index=0, dims=1024
# index=1, dims=1024
# index=2, dims=1024

2.6 首版模型详解：Qwen/Qwen3-Embedding-0.6B

属性值
模型 IDQwen/Qwen3-Embedding-0.6B
提供方Qwen（通义千问）
默认维度1024
可选维度32 / 64 / 128 / 256 / 512 / 768 / 1024
上下文长度32K tokens
接口类型OpenAI 兼容

选择理由：

  • 轻量级（0.6B 参数），API 响应速度快，适合批量向量化场景。
  • 32K 上下文窗口，足以覆盖绝大多数文档 chunk（当前分块 max_tokens=512）。
  • 支持 Matryoshka 表示学习，可通过 dimensions 参数灵活降维，后续可平滑切换维度而不需重新 embedding。
  • OpenAI 兼容接口，可直接复用 openai SDK，降低适配成本。
未来可选模型（按需切换）
  • Qwen/Qwen3-Embedding-4B — 2560 维，更高精度，适合质量敏感场景。
  • Qwen/Qwen3-Embedding-8B — 4096 维，最高精度。
  • BAAI/bge-m3 — 1024 维，多语言友好。
  • jina-embeddings-v4 — 2048 维，支持任务特定适配。

4. 核心组件设计

4.1 Embedding 适配器（EmbeddingAdapter）

封装云端 embedding API 调用，对外暴露项目内部规范化接口，不泄露第三方 SDK 类型。 设计原则与 DoclingChunkerAdapter 和 DoclingParserAdapter 保持一致。

接口定义（概念）

class EmbeddingAdapter:
    """OpenAI 兼容 embedding API 适配器。"""

    def __init__(self, *, config: EmbeddingConfig) -> None:
        self.config = config
        self._client: object | None = None

    def embed(self, texts: list[str]) -> list[EmbeddingResult]:
        """对文本列表进行批量向量化，返回按输入顺序排列的结果。"""

    def embed_single(self, text: str) -> EmbeddingResult:
        """对单个文本进行向量化。"""

@dataclass(frozen=True)
class EmbeddingResult:
    index: int
    embedding: list[float]

@dataclass(frozen=True)
class EmbeddingConfig:
    api_base_url: str       # https://router.tumuer.me/v1
    api_key: str            # Bearer token
    model: str              # Qwen/Qwen3-Embedding-0.6B
    dimensions: int         # 1024（默认）
    encoding_format: str    # "float"
    max_retries: int        # 3
    request_timeout: float  # 60.0（秒）
    batch_size: int         # 单次 API 调用最大文本数，默认 100
设计原则
  • 使用 openai Python SDK（用户已在项目中使用），不引入新的 HTTP 客户端依赖。
  • 支持自动重试（网络超时、5xx 错误），可配置重试次数和退避策略。
  • 输入文本列表长度超过 batch_size 时自动拆分为多个 API 调用。
  • 不向调用方暴露 openai 类型 —— 返回项目内部 EmbeddingResult。
  • API key 从配置中读取，不允许硬编码。

4.2 Embedding 服务（DocumentEmbeddingService）

管理向量化作业的完整生命周期：创建作业、执行向量化、持久化结果、处理失败。 设计模式与 DocumentChunkingService 对齐。

核心方法（概念）

class DocumentEmbeddingService:
    def __init__(self, *, session, adapter, config, model_readiness, shutdown_state): ...

    def run_initial_embedding(
        self, *, chunk_job, chunks: list[DocumentChunk],
    ) -> DocumentEmbeddingJob:
        """分块成功后自动触发首次向量化。"""

    def execute_queued_job(
        self, *, job: DocumentEmbeddingJob, chunks: list[DocumentChunk],
    ) -> DocumentEmbeddingJob:
        """对 API 层已创建的 QUEUED 作业执行向量化。"""

    def _create_job(self, *, chunk_job) -> DocumentEmbeddingJob: ...
    def _run_job(self, *, job, chunks, supersede_previous: bool) -> DocumentEmbeddingJob: ...
    def _batch_embed(self, chunks: list[DocumentChunk]) -> list[list[float]]: ...
    def _save_embeddings(self, *, job, chunks, vectors) -> None: ...
    def _supersede_previous_jobs(self, *, chunk_job_id, keep_job) -> None: ...

文本选择策略

向量化时使用 contextualized_text 作为主要输入（如果非空），否则 fallback 到 text。 这与 NormalizedChunk 的设计一致 —— contextualized_text 携带了文档结构上下文（标题路径等）， 对语义检索更友好。

索引建议

  • owner_user_id — 用户过滤
  • chunk_job_id — 按分块作业查询
  • parsed_document_id — 按解析文档查询
  • status — 状态过滤

5.2 Embedding 结果表（document_embeddings）

存储每个 chunk 对应的向量结果。首版将向量存储为 JSON 浮点数组，不写入 pgvector 类型的向量索引列。

字段类型说明
idUUID主键
embedding_job_idUUID (FK)关联的向量化作业
chunk_idUUID (FK)关联的 chunk
parsed_document_idUUID (FK)关联的解析结果（冗余）
owner_user_idUUID (FK)归属用户
sequence_indexInteger与对应 chunk 的 sequence_index 一致
modelString(128)嵌入模型名称
dimensionsInteger向量维度
embedding_jsonJSON浮点数组，如 [0.123, -0.456, ...]
token_countInteger向量化消耗的 token 数（从 API usage 获取）
created_atDateTime创建时间

索引建议

  • embedding_job_id — 按作业查询
  • chunk_id — 按 chunk 查询（单条向量查询）
  • owner_user_id — 用户过滤
  • (parsed_document_id, sequence_index) — 按文档顺序查询向量
为什么首版不写 pgvector 列？
  • 向量存储（pgvector 索引写入）和语义检索（相似度查询）是一个独立且复杂的变更，涉及 IVFFlat/HNSW 索引策略、距离度量选择、索引构建时机等。
  • 首版聚焦于"生成向量"这一独立步骤，验证云端 embedding API 的可用性、性能和成本。
  • 向量以 JSON 形式持久化后，后续向量存储变更可以直接读取已有 embedding 数据写入 pgvector 列，无需重新调用 embedding API。
  • 这符合 knowra 的渐进式架构原则：每个模块独立验证、独立上线。

6.2 自动触发流程

与"解析即分块"模式一致，分块成功后在同一后台任务内自动触发首次向量化： 

  run_parse_job()
      │
      ├─ 1. 解析成功 → parsed_documents + document_segments
      │
      ├─ 2. 分块成功 → document_chunk_job (succeeded) + document_chunks
      │
      └─ 3. 向量化（本变更新增）
            │
            ├─ 检查 embedding 功能是否启用
            │   ├─ 禁用 → 跳过，解析作业保持 succeeded
            │   └─ 启用 → 继续
            │
            ├─ 创建 embedding_job (status=queued)
            │
            ├─ 调用 DocumentEmbeddingService.run_initial_embedding()
            │   ├─ 批量收集所有 chunk 的 contextualized_text
            │   ├─ 调用 EmbeddingAdapter.embed(texts)
            │   ├─ 持久化 document_embeddings 记录
            │   └─ 更新 embedding_job 状态
            │
            └─ 向量化失败不回滚解析/分块结果
                ├─ 解析作业保持 succeeded ✓
                ├─ 分块作业保持 succeeded ✓
                └─ embedding_job 记录为 failed

POST /api/document-chunk-jobs/{chunk_job_id}/re-embed

Request Body (可选):
{
  "model": "Qwen/Qwen3-Embedding-4B",   // 切换模型
  "dimensions": 2560                     // 新维度
}

Response 202:
{
  "id": "uuid",
  "chunk_job_id": "uuid",
  "status": "queued",
  "model": "Qwen/Qwen3-Embedding-4B",
  "dimensions": 2560,
  "created_at": "2026-07-15T..."
}

错误场景:
- 409: 已有 queued/running 的向量化作业
- 503: 服务正在关闭
重新向量化的语义
  • 创建一个新的 queued 向量化作业，通过 BackgroundTasks 调度执行。
  • 支持切换模型或维度（因为云端 API 可随时切换模型）。
  • 新作业成功后，旧 succeeded 作业被标记为 superseded。
  • 不使用旧 embedding 结果，重新调用云端 API 生成新向量。
  • 失败时保留旧活跃结果。
  • 不重新解析或重新分块 —— 直接使用已有 document_chunks 表中的文本。

7.5 权限模型

所有 embedding API 均遵循与 chunk/parse API 相同的权限模型：

  • 只能访问归属当前用户的 embedding_job 和 embedding 结果。
  • 请求其他用户的资源时返回非 2xx 状态码且不暴露详情。

8. 配置管理

8.1 新增环境变量

遵循项目既有的 DOCUMENT_* 配置命名规范，新增独立的 embedding 配置组：

环境变量默认值说明
DOCUMENT_EMBEDDING_ENABLED true 向量化功能开关
DOCUMENT_EMBEDDING_API_BASE_URL https://router.tumuer.me/v1 云端 embedding API 地址
DOCUMENT_EMBEDDING_API_KEY "" API 密钥（Bearer token），敏感信息，必须通过 .env 配置
DOCUMENT_EMBEDDING_MODEL Qwen/Qwen3-Embedding-0.6B 嵌入模型名称
DOCUMENT_EMBEDDING_DIMENSIONS 1024 向量维度
DOCUMENT_EMBEDDING_ENCODING_FORMAT float 向量返回格式
DOCUMENT_EMBEDDING_BATCH_SIZE 100 单次 API 调用最大文本数
DOCUMENT_EMBEDDING_MAX_RETRIES 3 API 调用失败最大重试次数
DOCUMENT_EMBEDDING_REQUEST_TIMEOUT 60.0 单次 API 调用超时时间（秒）

8.2 .env.example 新增片段

# ── 文档向量化（云端 embedding）──
DOCUMENT_EMBEDDING_ENABLED=true
DOCUMENT_EMBEDDING_API_BASE_URL=https://router.tumuer.me/v1
DOCUMENT_EMBEDDING_API_KEY=your_api_key_here
DOCUMENT_EMBEDDING_MODEL=Qwen/Qwen3-Embedding-0.6B
DOCUMENT_EMBEDDING_DIMENSIONS=1024
DOCUMENT_EMBEDDING_ENCODING_FORMAT=float
DOCUMENT_EMBEDDING_BATCH_SIZE=100
DOCUMENT_EMBEDDING_MAX_RETRIES=3
DOCUMENT_EMBEDDING_REQUEST_TIMEOUT=60.0
配置原则
  • DOCUMENT_EMBEDDING_API_KEY 为敏感信息，绝对不能硬编码，必须通过 .env 配置，且不提交到版本控制。
  • 所有 DOCUMENT_EMBEDDING_* 变量独立管理，不复用既有 DOCUMENT_CHUNK_* 或 DOCUMENT_MODEL_* 变量。
  • 这与项目已有的 DOCUMENT_MODEL_*（bootstrap 用）和 DOCUMENT_CHUNK_*（分块用）的命名隔离原则一致。

9. 前端体验预期

9.1 分块后展示向量化状态

向量化中 展示 loading 状态，文案如"正在生成向量..."，禁止重复触发。
向量化完成 展示 ✓ 完成，显示向量维度、模型名称。提供查看向量预览入口。
向量化失败 展示错误反馈，保留重新向量化入口。不影响分块完成状态的展示。
未开始 如果向量化功能被禁用或配置缺失，展示"暂未向量化"状态。
边界说明 前端 MUST NOT 将向量化完成表述为"已可搜索"或"已可问答"。
注意：前端不直接展示原始向量数组（1024 个浮点数），预览可展示前几个维度值和维度数。

10. Graceful Shutdown 与错误处理

10.1 关闭收尾

与解析作业和分块作业对齐：

  • 关闭期间，将 queued 和 running 的向量化作业标记为 failed，error_code=process_shutdown。
  • 已完成的作业（succeeded、failed、superseded）不修改。
  • 关闭期间拒绝创建新的向量化作业（返回 503 Service Unavailable）。

10.2 错误码定义

error_code场景
api_error云端 API 返回非 2xx 状态码（网络超时、认证失败、限流等）
model_unavailable请求的模型在云端不可用（模型名称错误或下线）
embedding_disabled向量化功能配置为禁用
invalid_response云端 API 返回数据格式异常（维度不匹配、缺少 embedding 等）
process_shutdown进程关闭导致作业未完成

10.3 重试策略

适配器层通过 max_retries 配置自动重试临时性错误（网络超时、429 限流、5xx）。 重试使用指数退避（exponential backoff）。超过最大重试次数后将作业标记为 failed。

12. 风险与后续扩展

12.1 已知风险

云端 API 可用性
  • tumuer.me 为第三方服务，存在不可用或限流风险。
  • 缓解措施：配置超时和重试策略；向量化失败不阻塞解析和分块成功状态。
  • 后续可考虑支持多个 embedding 服务提供方作为 fallback。
API 调用成本
  • 大批量文档向量化会产生 API 调用费用。首版不做成本控制（如每日限额）。
  • 后续可在配置中增加 rate limiting 或成本追踪。
JSON 向量存储体积
  • 每个 1024 维向量以 JSON 数组存储约 8-12KB，大量文档可能占用较大数据库空间。
  • 这是过渡方案。后续向量存储变更中，向量将从 JSON 列迁移到 pgvector vector(1024) 类型列， 届时 embedding_json 列可废弃。

12.2 后续扩展方向

方向说明独立变更
向量存储（pgvector） 将 embedding_json 迁移到 vector(N) 列，创建 IVFFlat/HNSW 索引 add-vector-storage
语义检索 基于 pgvector 相似度查询实现 chunk 检索，返回 Top-K 相关片段 add-semantic-search
RAG 问答 检索增强生成：用户提问 → 检索相关 chunk → LLM 生成带引用回答 add-rag-qa
多模型支持 支持同时维护多个 embedding 模型的向量版本（用于 A/B 测试或模型迁移） add-multi-model-embedding
本地模型推理 支持本地部署 embedding 模型（如通过 Ollama / vLLM），减少云端依赖 add-local-embedding

13.1 前置能力依赖

能力状态关键产物

document-embedding📋 本变更document_embedding_jobs、document_embeddings

13.2 现有 document-chunking spec 中的预留

现有 document-chunking spec 中已明确声明：

Requirement: 首版分块范围边界
"系统 SHALL 将首版文档分块限定为生成可追溯 chunk，不在本能力中实现 embedding、向量索引、语义检索或 RAG。"

本变更正是对该边界的补充 —— 在分块能力稳定后，独立实现向量化模块。 嵌入模型的向量化结果在 document_embeddings 表中持久化后， 后续的"向量存储（pgvector）"变更只需读取已有数据并建立向量索引， 不需要重新调用 embedding API。
