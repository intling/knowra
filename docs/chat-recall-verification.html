对话召回验证

基于 pgvector 的语义搜索试验台 — 输入问题 → 向量化 → 跨文档相似度检索 → LLM 生成回答 → 展示召回结果与提示词

1. 背景与目标

当前状态

向量化转译分块流程已经验证成功（7 项完整性检查）。知识库已完成 上传 → 解析 → 分块 → 向量化 全链路， document_embeddings.embedding_vector（pgvector Vector(2560)） 列存储了大量向量数据。但目前 没有任何搜索/召回代码，向量处于"只存不查"状态。

Upload ──▶ Parse ──▶ Chunk ──▶ Embedding ──▶ ??? SEARCH ??? PDF/MD Docling Token 512 Qwen3-Emb-4B ↑ TXT/PPTX → Markdown + context 2560d pgvector WE ARE HERE

目标

  1. 搭建一个可对话的页面，输入自然语言问题，无需手动选择文档
  2. 调用后端语义搜索端点，跨所有已向量化的文档召回相关分块
  3. 调用 LLM 生成带来源引用的答案，验证端到端 RAG 质量
  4. 展示召回结果与 AI 回答并列：分块文本、相似度分数、来源文档、LLM 回答
  5. 展示实际发送给 LLM 的提示词（可折叠，用于调试和 prompt 迭代）
💡 设计决策：为何本期接入 LLM 而非后续再补？

1. RAG 的检索质量只能通过答案质量来验证。余弦距离是代理指标——高分块可能缺少前置上下文导致 LLM 编造，多文档信息冲突时 LLM 随机选择，上下文过长时 LLM 忽略关键信息。这些场景在"只看分块文本"时完全不可见。

2. OpenAI SDK 已在项目中（用于文档向量化）。从 client.embeddings.create 到 client.chat.completions.create 是同一個 SDK 实例的同一个方法族，不是"新增一个系统"，而是新增一个 ~60 行的 Adapter。

3. 行业最佳实践是先跑通端到端基线，再逐组件优化。RAG 组件间紧耦合：检索策略变了 prompt 也要调，分块大小变了 LLM 上下文窗口也要调。分步构建意味着每个阶段推倒重来。

4. LLM 本身就是最好的验证工具。看 10 条 AI 回答就知道检索质量（答案是否引用上下文？是否标注来源？），而纯检索需要人工逐条检查 50 个分块。

明确不做（本期范围外）

  • 不做混合搜索（BM25 + 向量）— 先用纯语义搜索作为基线
  • 不做 Reranker — 先用 pgvector cosine distance 原始排序
  • 不做多轮对话 — 先聚焦单轮问答验证。详见下方「多轮对话 & 流式输出决策」分析
  • 不做分页 — 单次返回 top_k ≤ 50 条结果
  • 不做流式输出 — LLM 回答一次性返回，简化前端实现。详见下方「多轮对话 & 流式输出决策」分析

以上 5 项均已列入 第 14 节「后续规划」，将在后续 Phase 2–5 中逐阶段落实。本阶段聚焦单轮 RAG 端到端基线验证。

2. 多轮对话 & 流式输出决策分析

📋 决策摘要：本阶段两者均不做，但流式输出做好架构预留。

2.1 多轮对话 — 强烈建议延后

维度分析
当前阶段目标 验证 RAG 端到端质量（检索 → 生成 → 引用准确性），单轮足以覆盖所有验证场景
复杂度增量 需要对话历史存储、上下文窗口管理、追问 vs 新话题判断、prompt 策略分层。预估新增 300–500 行后端代码
依赖关系 多轮对话依赖单轮 RAG 先跑通——检索质量不过关，多轮毫无意义。分块策略、prompt 模板、召回精度都需要单轮验证稳定后再进入多轮
行业实践 几乎所有 RAG 项目都是先跑通单轮基线，再叠加对话历史。LangChain、LlamaIndex 的 quickstart 均为单轮优先。过早引入多轮会导致调试复杂度指数增长
风险 如果本阶段强行加入多轮：(1) 问题定位困难——答案不好时无法判断是检索问题还是历史污染；(2) prompt 调试困难——上下文窗口混入历史消息后难以隔离变量

结论：严格延后至 Phase 2。当前设计文档“后续规划”中的 Phase 2 定位完全正确。先在本阶段验证单轮 RAG 基线的检索质量和 LLM 引用准确性，再考虑历史管理。

2.2 流式输出 — 建议延后，做好架构预留

维度分析
对验证目标的价值 零——流式输出不改变答案内容，只改变答案的呈现方式（逐 token 展示 vs 一次性返回）
实现成本 后端 ~50 行（SSE endpoint）+ 前端 ~100 行（流式消费 ReadableStream），总成本可控但不低
OpenAI SDK 支持 stream=True 一行启用，SDK 原生支持。ChatAdapter.generate() 加一个参数即可
调试友好性 对于验证/调试工具，非流式更优——可以一次性观察完整 prompt 和完整 response，方便对比检索结果与 AI 回答。流式输出需要在 Network 面板拼接 chunks
行业实践 流式输出已成为 chat UI 标配（ChatGPT、Claude、Kimi 均为流式），但这是面向最终用户的体验优化，非验证工具所需

2.3 架构预留方案

虽然本阶段不做流式输出，但在 ChatAdapter 设计上做出最小预留，确保后续零破坏性添加：

@dataclass(frozen=True)
class ChatConfig:
    """Immutable configuration for the LLM chat adapter.

    Mirrors EmbeddingConfig pattern — all connection parameters,
    model selection, and generation knobs captured in one place.
    """

    api_base_url: str
    api_key: str
    model: str
    temperature: float
    max_tokens: int
    request_timeout: float
    max_retries: int

    @classmethod
    def from_settings(cls, settings=None) -> "ChatConfig":
        if settings is None:
            settings = get_settings()
        return cls(
            api_base_url=settings.chat_api_base_url,
            api_key=settings.chat_api_key,
            model=settings.chat_model,
            temperature=settings.chat_temperature,
            max_tokens=settings.chat_max_tokens,
            request_timeout=settings.chat_request_timeout,
            max_retries=settings.chat_max_retries,
        )

    def snapshot(self) -> dict[str, Any]:
        return {
            "api_base_url": self.api_base_url,
            "model": self.model,
            "temperature": self.temperature,
            "max_tokens": self.max_tokens,

7.3 ChatAdapter (backend/app/services/chat_adapter.py，新增)

import time
from dataclasses import dataclass

from openai import APIConnectionError, APIStatusError, APITimeoutError, OpenAI

from app.services.chat_config import ChatConfig


class ChatError(Exception):
    """Base exception for all chat operations."""
    pass


class ChatAPIError(ChatError):
    """Raised when the chat API call fails after all retries."""

    def __init__(self, message: str, status_code: int | None = None) -> None:
        super().__init__(message)
        self.status_code = status_code


@dataclass(frozen=True)
class ChatResult:
    """A single chat completion result.

    Attributes:
        content: The generated text.
        total_tokens: Total tokens consumed (prompt + completion).
        prompt_tokens: Tokens consumed by the input messages.
        completion_tokens: Tokens generated in the response.
    """

    content: str
    total_tokens: int
    prompt_tokens: int
    completion_tokens: int


class ChatAdapter:
    """Encapsulates an OpenAI-compatible ``POST /v1/chat/completions`` endpoint.

    Follows the same pattern as EmbeddingAdapter: config injection,
    retry with exponential backoff, no SDK types leaked to callers.
    """

    def __init__(
        self,
        *,
        config: ChatConfig,
        client: object | None = None,
    ) -> None:
        self.config = config
        if client is not None:
            self._client = client
        else:
            self._client = OpenAI(
                base_url=config.api_base_url,
                api_key=config.api_key,
                timeout=config.request_timeout,
            )

    def generate(self, messages: list[dict[str, str]]) -> ChatResult:
        """Send *messages* to the chat API and return the completion.

        Retries on transient errors (timeout, 5xx, connection) with
        exponential backoff.  Non-retryable errors (4xx) fail fast.
        """
        last_exception: Exception | None = None

        for attempt in range(self.config.max_retries + 1):
            try:
                response = self._client.chat.completions.create(
                    model=self.config.model,
                    messages=messages,
                    temperature=self.config.temperature,
                    max_tokens=self.config.max_tokens,
                )
                choice = response.choices[0]
                usage = response.usage
                return ChatResult(
                    content=choice.message.content or "",
                    total_tokens=usage.total_tokens if usage else 0,
                    prompt_tokens=usage.prompt_tokens if usage else 0,
                    completion_tokens=usage.completion_tokens if usage else 0,
                )
            except Exception as exc:
                last_exception = exc
                if not self._should_retry(exc, attempt):
                    break
                if attempt < self.config.max_retries:
                    time.sleep(2 ** attempt)

        raise self._wrap_error(last_exception)

    def _should_retry(self, exception: Exception, attempt: int) -> bool:
        if attempt >= self.config.max_retries:
            return False
        if isinstance(exception, APITimeoutError):
            return True
        if isinstance(exception, APIStatusError):
            return 500 <= exception.status_code < 600
        return isinstance(exception, APIConnectionError)

    @staticmethod
    def _wrap_error(exception: Exception | None) -> ChatError:
        if exception is None:
            return ChatAPIError("Unknown chat API error")
        if isinstance(exception, APIStatusError):
            return ChatAPIError(str(exception), status_code=exception.status_code)
        return ChatAPIError(str(exception))

front/src/api/search.ts

// ── Request ────────────────────────────────────────────
export interface SearchRequest {
  query: string
  top_k?: number           // default 5, range 1–50
}

// ── Response types ─────────────────────────────────────
export interface AnswerTokens {
  prompt: number
  completion: number
  total: number
}

export interface SearchResultItem {
  rank: number
  score: number
  chunk_id: string
  parsed_document_id: string
  document_name: string
  sequence_index: number
  text: string | null
  contextualized_text: string | null
  token_count: number | null
  heading_path: string[] | null
  page_numbers: number[] | null
}

export interface SearchResponse {
  query: string
  query_embedding_preview: number[]
  embedding_model: string
  embedding_dimensions: number
  top_k: number
  total_searched: number
  searched_document_count: number
  search_time_ms: number
  answer: string
  answer_tokens: AnswerTokens
  chat_model: string
  results: SearchResultItem[]
}

// ── API function ───────────────────────────────────────
/**
 * 跨文档语义搜索 + LLM 生成。
 * 搜索所有已向量化文档并生成 AI 回答。
 *
 * @param request - { query, top_k? }
 * @returns 搜索结果 + LLM 回答
 */
export async function searchChunks(
  request: SearchRequest,
): Promise<SearchResponse> {
  const response = await fetch(
    buildApiUrl("/search"),
    {
      method: "POST",
      headers: { "Content-Type": "application/json", ...commonHeaders() },
      body: JSON.stringify(request),
    },
  )
  if (!response.ok) {
    const detail = await getErrorMessage(response)
    throw new SearchApiError(response.status, detail)
  }
  return response.json()
}

13. 验证标准

13.1 主观验证（手动测试）

  • 上传 2–3 份内容明确但主题不同的文档
  • 输入与某文档特定段落高度相关的问题
  • 验证 LLM 回答引用准确性：答案中的文档名、页码是否与检索结果一致
  • 验证幻觉检测：问一个文档中没有的内容，检查 LLM 是否正确回复"根据现有资料无法回答"
  • 验证跨文档综合：当答案需要多个文档的信息时，LLM 是否正确引用每个来源

13.2 客观检查项

项目预期
分数单调性rank 与 score 严格单调递增
文本完整性所有结果 text 不为 null 或空
去重chunk_id 不重复
查询向量维度与 embedding_dimensions 一致
模型一致性查询与文档使用同一 embedding_model
top_k 生效结果数 ≤ top_k
search_time_ms存在且为正值
searched_document_count与实际搜索的文档数一致
answer 非空answer 不为 null
answer_tokensprompt + completion = total

13.3 边界情况

  • 系统无任何向量化数据 → 404 "No embeddings found in the system"
  • top_k 大于总分块数 → 返回全部
  • 查询包含特殊字符 / emoji → 向量化正常进行
  • 非常短的查询（1–2 个词）→ 返回余弦距离最近的分块
  • chat 未配置 → 503 "Chat generation is disabled"
  • LLM API 超时 → 502 "Failed to generate answer"
