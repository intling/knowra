## Why

knowra 当前将所有请求解析为固定默认用户，搜索范围和浏览器对话存储也未按真实账号隔离，无法兑现私有资料的访问边界。需要建立可登录、可管理、可撤销访问权限的用户体系，让资料接入、检索和带引用问答都具有明确的身份与权限。

## What Changes

- 增加邮箱密码注册、登录、退出、持久会话、资料修改和密码修改，以及对应的前端页面和状态反馈。
- 增加管理员、成员、只读用户角色；由后端强制执行权限校验，提供用户管理和管理员初始化方式。
- **BREAKING**：业务 API 从默认用户模式切换为真实会话认证；未登录返回可诊断的 401，权限不足返回 403。
- **BREAKING**：检索、知识库统计、缓存和浏览器对话均绑定真实用户；管理员身份不隐含读取他人私有资料的权限。
- 通过新增 Alembic 迁移扩展账号和会话结构；保留历史资源外键，禁止首个注册者自动继承默认用户资料或取得管理员身份。
- 同步配置模板、根 README、前后端 README 与章程，补充迁移、运维及完整验收证据。
- 本轮不引入组织/团队共享、第三方登录、SSO、MFA、邮件验证、邮件找回密码或服务端对话同步；这些能力需要独立的数据与外部服务契约。

## Capabilities

### New Capabilities

- `user-authentication`：注册登录、密码保护、可撤销会话、CSRF 防护、个人资料与密码管理。
- `user-authorization`：角色权限、用户管理、管理员初始化、末位管理员保护与全链路用户数据隔离。
- `user-account-ui`：登录注册、账户管理、用户管理、路由守卫、会话过期与浏览器对话隔离。

### Modified Capabilities

- `basic-user-foundation`：用真实会话替换默认用户解析，扩展用户响应和前端身份状态，解除原阶段对认证入口的限制。
- `semantic-search`：将“全部文档”限定为当前用户拥有的有效文档，按用户隔离统计、检索与缓存。
- `backend-module-logging`：删除默认用户解析与 503 相关日志要求，改为认证、会话与 401 日志要求。

## Impact

- 后端：`models/user.py`、新增会话模型、`api` 认证依赖与路由、`services/users.py`、搜索/缓存/指纹服务、配置、管理命令及 Alembic。
- 前端：统一 API client、现有独立 fetch 调用、user/chat store、router、账户入口与新增页面；沿用书房批注本视觉语言并支持移动端。
- 契约：新增 `/api/auth/*`、个人账户更新和管理员用户管理接口；现有业务接口增加认证/授权要求。
- 安全：密码只存自适应哈希；浏览器会话通过 HttpOnly Cookie 传输；用户信息响应与日志不得包含密码和会话原文。
- 依赖：设计由 `pi` 的 `dtmaas/claude-opus-5-5` 提供，生产实现由当前模型完成；最终设计保留原始输出与采纳说明。
- 验收：先核对现有基线，再添加并运行前后端红测试；遵循仓库红测试评审门禁后实现，最终运行测试、静态检查、构建、迁移与本地浏览器验证。
- 迁移与回滚：部署前备份；仅新增迁移，不改写历史迁移；回滚服务时必须关闭外部访问，避免恢复默认用户旁路。
