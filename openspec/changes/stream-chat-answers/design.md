# 流式问答设计

## 接口契约

继续使用 `POST /api/search` 及原 `SearchRequest`。未声明 SSE 时保持原 `SearchResponse` JSON；主界面通过统一 `apiFetch`、Cookie、trace ID 和 `AbortSignal` 发送 `Accept: text/event-stream`。

流响应为 UTF-8 SSE，设置 `Cache-Control: no-cache`、`X-Accel-Buffering: no`，等待期间发送注释心跳。每帧使用 `event` 和 JSON 编码的 `data`：

| event | data | 含义 |
| --- | --- | --- |
| `status` | `{"stage":"searching"}` 或 `{"stage":"generating"}` | 实际处理阶段 |
| `metadata` | 正文为空、用量为 null 的 `SearchResponse` | 生成前的模式、来源、覆盖和检索信息 |
| `delta` | `{"delta":"新增正文"}` | 直接追加的正文；不传模型推理或供应商内部对象 |
| `done` | 最终 `SearchResponse` | 最终正文、完整性、来源、累计实际用量和生成错误；唯一正常结束事件 |
| `error` | `{"detail":"可读的安全错误"}` | 流开始后的不可恢复错误，不返回内部异常或其他用户资料 |

鉴权、额度、模型配置和显式文档范围在开始响应前校验，保持原 401/404/422/429/503 及具体错误原因。供应商生成失败沿用最终 `SearchResponse.generation_error`。缓存命中或无需模型的澄清可以直接结束，不伪造 token 增量。客户端缺少 `done` 时视为连接中断，不把已读到的正文当作完成。

## 后端

保留同步 `SearchService.search` 入口，复用异步编排入口和原策略、缓存、来源与续写逻辑。生成通过可选异步增量回调逐段传递到有界 SSE 队列，不在事件循环执行阻塞检索网络调用。保留现有总截止时间、首 token 超时、熔断及 403 兼容重试。

模型适配器边收集边通知回调，最终仍返回 `ChatResult`。一旦正文已交付，不重新播放同次生成，避免网络重试重复正文。续写正常接续并累计供应商实际用量；本次流中断或超时时保留已经交付的正文，设 `answer_incomplete=true`，不缓存、不计成功额度。首次生成在正文出现前失败仍使用原降级语义。

额度依赖生命周期覆盖整个响应流，不能在返回 `StreamingResponse` 时释放预留。流结束后仅完整成功回答保留占用；取消会传播到生成任务并关闭供应商流，依赖随后关闭客户端和数据库会话。生成、来源读取仍使用认证用户与原文档范围，不增加身份旁路。
同步检索准备只在线程中执行；取消时等待有界读取退出，再释放数据库和网络客户端。HTTP 发送异常也须显式关闭响应生成器，不能依赖异步生成器稍后的垃圾回收。

## 前端

`searchChunks` 增加可选事件回调和取消信号；原调用继续读取 JSON。SSE 解码使用流式 `TextDecoder`，支持中文跨字节、事件跨网络块、多帧合并、LF/CRLF、注释和多行 data。未知事件可以跳过；非法已知事件、显式错误和缺少终帧均返回可读错误，结束或失败时关闭 reader。

主对话接收 metadata 后进入真实生成状态，delta 追加到原气泡；生成期间输入保持禁用，完成后统一写入最终响应。增量在内存更新并按浏览器帧合并渲染，不逐 token 写入 localStorage。断流保留正文、来源和未完成提示；正文出现前失败显示原请求错误。新一轮的对话历史不包含仍在生成的答案。

切换对话不把旧增量写入新对话；卸载、切换用户或删除正在生成的对话会取消对应请求。刷新后将遗留的在途记录归为已中断，恢复输入能力。流式更新仅在用户靠近消息底部时跟随消息容器滚动，用户向上阅读时不抢回位置，不使用 `scrollIntoView`。

## 视觉与可访问性

复用项目 paper / ink / brand 令牌和本地字体。等待时保留轻量占位；生成时显示呼吸状态点、尾部光标和一次性短渐入，完成后移除。保持稳定 Markdown 节点，不通过逐字重置动画延迟实际内容。生成过程中不反复向读屏播报每个 token，通过独立 `role=status` 提示开始/完成。减少动态效果模式关闭闪烁、呼吸、位移与平滑滚动，保留静态状态标识。来源、复制和最终用量沿用原组件，不制造零 token 统计。
