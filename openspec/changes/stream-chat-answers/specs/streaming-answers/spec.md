# 新增需求

## Requirement: 真实正文流式交付

系统 MUST 在模型生成结束前向已认证用户交付正文增量，并保持现有回答模式、来源和用量语义。

### Scenario: 正常生成

- GIVEN 已通过身份、额度与资料范围校验的流式请求
- WHEN 模型生成第一段正文且尚未结束
- THEN 客户端已收到 metadata 和第一段 delta，并能够阅读正文
- AND done 携带完整正文、真实来源与最终累计用量

### Scenario: 长度续写

- GIVEN 首次输出以 length 结束
- WHEN 系统按原有有界策略继续生成
- THEN 增量按顺序追加，不重复已经交付的正文
- AND 最终正文与累计用量与原同步行为一致

### Scenario: 中断或取消

- GIVEN 已经显示部分正文与真实来源
- WHEN 上游异常、连接断开、超时或用户离开工作区
- THEN 保留可见正文并提示未完成，取消连接时关闭上游流
- AND 本轮不写成功缓存、不保留成功额度占用

## Requirement: 兼容与身份边界

系统 MUST 保留原 JSON 入口和已认证用户作用域。

### Scenario: 流开始前拒绝

- GIVEN 未登录、不可见资料、格式错误、额度用尽或模型未配置
- WHEN 请求流式问答
- THEN 返回原 HTTP 错误码和具体可读原因，不调用生成模型

### Scenario: 流期间的额度

- GIVEN 账户成功额度上限为一次
- WHEN 第一个请求仍在生成
- THEN 预留仍有效，并发请求因超限被拒绝
- AND 第一个请求失败或取消后可重新提问

### Scenario: 切换或刷新

- GIVEN 一个对话正在生成
- WHEN 用户切换对话
- THEN 后续增量只更新原对话
- WHEN 用户退出身份、卸载工作区或删除原对话
- THEN 取消对应流，不向新身份写入内容
- WHEN 浏览器加载遗留的在途记录
- THEN 将其显示为已中断并允许继续发送

## Requirement: 安静且可访问的生成反馈

界面 MUST 持续显示真实生成阶段，并尊重减少动态效果设置。

### Scenario: 生成中与完成

- GIVEN metadata 或正文增量已到达
- WHEN 生成仍在进行
- THEN 正文随增量更新，显示生成光标和状态提示，禁止重复发送
- WHEN 收到 done
- THEN 移除生成效果并恢复输入，展示最终引用和真实用量

### Scenario: 减少动态效果与阅读位置

- GIVEN 系统启用 prefers-reduced-motion 或用户正在向上阅读
- WHEN 新增正文到达
- THEN 关闭动画并保留静态生成状态，且不抢走用户的阅读位置
