# 自适应 RAG 回答策略

## Why

当前主对话把检索命中当作大模型回答的前提：普通问题零召回时直接返回固定拒答，有资料时又用提示词禁止任何通用知识补充。演示账号的推荐问题“总结这些资料的核心观点”也被当成向量查询，无法选取需要总结的文档，导致知识助手不能正常交流或概览已有资料。

## What Changes

- 默认采用自适应回答：明确闲聊和明确要求通用知识的请求直接生成；其他知识问题可优先检索，零召回、空知识库时继续使用通用知识，不编造资料来源。
- 对明确依赖私有资料的问题，缺少依据时解释缺少的资料并给出下一步；不把通用推断冒充文档结论。
- 识别文档概览/总结意图，按当前用户可见的文档范围读取分块，不使用问题的相似度阈值筛选文档；返回总结范围与覆盖信息。
- `POST /api/search` 增加可选 `document_ids`，响应增加 `answer_mode`、`retrieval_status`、`summary_coverage`。保留现有路径、身份/权限、模型配置、额度、缓存隔离与诊断字段。
- 主对话按回答模式展示：通用回答轻量标注“基于通用知识”，省略零引用统计和无依据告警；资料回答保留真实来源；需要澄清时显示可操作的引导。
- 本期不新增流式接口、模型选择界面、附件索引等待流程、跨设备会话、知识图谱或检索算法。

## Capabilities

### New Capabilities

- `adaptive-rag`: 自动回答路由、零召回后的通用回答、资料依赖澄清和有界文档总结。

### Modified Capabilities

- `semantic-search`: 文档范围校验、自适应回答元信息、空知识库下的正常问答与检索故障语义。
- `chat-generation`: 按模式组装提示词，允许有明确归属的通用知识补充，保留资料事实的可追溯性。
- `chat-recall-ui`: 按回答模式展示来源和状态，兼容浏览器内旧对话。

## Impact

- 后端：搜索 schema、路由和编排服务；新增独立的回答策略与文档总结上下文模块，复用现有 ChatAdapter 与用户作用域。
- 前端：搜索 API 类型、ChatArea、AnswerPanel、欢迎说明与对应测试；来源组件继续服务真实资料。
- API：新增字段向后兼容；**BREAKING** 空知识库的普通问答由 404 改为 200，零召回的回答由固定句改为模型生成或针对性澄清。资料越权请求统一 404 并提供不泄露资源归属的可读原因。
- 不改数据库 schema，不新增依赖或环境变量。普通零召回问答开始调用已配置的对话模型，产生正常模型费用；成功回答沿用账号问答额度，澄清和失败释放额度。
- 验收：普通问题在零向量和零召回时有模型正文；推荐总结问题在存在资料时有真实文档上下文；通用回答没有红色无依据提示；他人/删除资料不能进入 prompt、来源、缓存或总结覆盖计数。
- 文档同步：根目录、前后端 README 与端侧 AGENTS.md 更新默认问答行为和 API 契约。
- 回滚：回滚前后端代码即可，无迁移。回答策略版本参与响应缓存命名空间；旧浏览器响应缺少模式字段时保留原有展示，避免错误解释旧记录。部署与正式归档另行执行。
