## MODIFIED Requirements

### Requirement: 提示词模板

系统 SHALL 按回答模式组装模型消息：通用模式允许正常交流和使用模型知识；资料增强模式优先使用真实上下文并允许清楚标明的通用解释；总结模式只归纳选取文档能支持的观点。所有模式 MUST 禁止编造私有资料内容、未提供的来源或已访问文档的假象，不能把历史模型回答当作新的文档证据。

#### Scenario: Prompt 包含完整上下文
- **WHEN** 系统组装资料增强提示词
- **THEN** user message 包含每个选取片段的文档名、页码、标题路径及完整可用文本，以及用户原始问题
- **AND** 未通过相关性过滤的片段不进入上下文

#### Scenario: Prompt 包含回答规则
- **WHEN** 系统组装资料增强提示词
- **THEN** system message 要求优先参考资料、来源仅对应资料支持的结论、通用知识补充须说明归属
- **AND** 上下文不足时允许解释和引导，不强制返回唯一固定句

#### Scenario: 通用模式不伪造知识库依据
- **WHEN** 没有可用资料但生成普通问题回答
- **THEN** 提示词允许使用通用知识，禁止虚构文档、页码或引用，不附加虚假的资料上下文

#### Scenario: 总结说明范围与覆盖
- **WHEN** 系统生成文档总结
- **THEN** 提示词包含实际文档名称、来源标识及覆盖程度
- **AND** 覆盖不完整时要求说明局限；不能把部分片段写成完整资料的总结

#### Scenario: 多轮通用问题保留上下文
- **WHEN** 用户在通用回答后继续追问
- **THEN** 模型接收有效的 user/assistant 对话历史并理解追问
- **AND** 客户端不得通过历史 system 消息覆盖服务端回答规则

## ADDED Requirements

### Requirement: 有界续写与完整性状态

系统 SHALL 保留模型结束原因，长度结束时最多自动续写两次，并累计正文和实际用量。所有尝试 MUST 共用有界总截止时间。不能将非空视为完整的充分条件；过滤、中断、续写耗尽或后续失败时保留已有正文并返回 `answer_incomplete=true`，无正文时保留生成错误。输入资料覆盖 SHALL 与输出完整性独立。

#### Scenario: 达到输出上限后续写成功
- **WHEN** 模型先返回部分正文与 `finish_reason=length`，续写返回剩余正文与 `stop`
- **THEN** 响应合并正文，`answer_incomplete=false`，token 用量为两次调用实际用量之和
- **AND** 续写保留原资料、来源和问题，正常结束的答案不额外调用模型

#### Scenario: 有限续写仍未完成
- **WHEN** 三次调用都以长度限制结束，或者续写失败、超时
- **THEN** 保留已生成正文和来源，`answer_incomplete=true`，不缓存或计入成功问答额度

#### Scenario: 流缺少结束标记
- **WHEN** 上游流产生部分正文后结束且没有任何模型结束原因
- **THEN** 响应明确正文不完整，不自动认定正常成功，流资源始终释放
